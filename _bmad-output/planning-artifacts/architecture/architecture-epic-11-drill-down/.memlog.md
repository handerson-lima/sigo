- (constraint) O sistema requer navegação aninhada exata de Loteamento até Equipe, com breadcrumbs correspondentes (conforme sprint-change-proposal-2026-09-24.md).
- (constraint) O banco de dados requer coleções/subcoleções aninhadas ou referências estruturadas para suportar a hierarquia.
- (decision) AD-1 — Hierarquia Firestore Aninhada. Binds: Firestore schema. Prevents: consultas planas ineficientes e perda de parentesco hierárquico. Rule: Os dados devem ser estruturados em subcoleções: `loteamentos/{idLoteamento}/quadras/{idQuadra}/lotes/{idLote}/setores/{idSetor}/equipes/{idEquipe}`. A entidade `Obras` servirá como container ou será substituída no nível raiz.
- (decision) AD-2 — Rotas de Drill-down Modulares (GoRouter). Binds: app_router. Prevents: ausência de contexto de URL para deep-linking nos 5 níveis. Rule: As rotas devem seguir a hierarquia estrita: `/loteamentos/:lId/quadras/:qId/lotes/:loId/setores/:sId/equipes/:eId`. Cada submódulo de rota aninha os paths para preservar o contexto hierárquico na URL.
- (decision) AD-3 — Atribuição de permissões (ACL) localizada no nó. Binds: RH e Gestão de Membros. Prevents: usuários com acesso total desnecessário a toda a obra. Rule: A atribuição de um membro agora ocorre num nível específico (ex: Lote ou Equipe).
