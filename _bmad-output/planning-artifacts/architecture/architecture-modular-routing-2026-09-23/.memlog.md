- (constraint) Brownfield: go_router ^18.0.1 já em uso; GoRouter.routes aceita List<RouteBase>; cada feature já segue data/domain/presentation; 14 features identificadas; AccessGuard é o mecanismo de autorização por rota.
- (decision) AD-1 — Uma lista por feature: cada feature exporta List<RouteBase> get routes via arquivo routing/<feature>_routes.dart colocado dentro da feature. Binds: all. Prevents: router monolítico crescendo com cada feature, conflitos de merge, imports cruzados massivos. Rule: nenhuma feature importa routing de outra feature; só o router central importa *_routes.dart.
- (decision) AD-2 — Spread-only composition: app_router.dart compõe via spread (...featureRoutes) sem nesting, wrapper, ou factory intermediária. Binds: app_router.dart. Prevents: camada de abstração desnecessária sobre go_router e indirection que dificulta debugging. Rule: routes: [...authRoutes, ...devRoutes, ...construtoraRoutes, ...obraRoutes, ...].
- (decision) AD-3 — Redirect e guards ficam no router central: redirect de auth e trustedDev continua centralizado no routerProvider; AccessGuard continua no builder de cada rota dentro da feature. Binds: auth, AccessGuard. Prevents: cada feature implementando lógica de redirect divergente. Rule: GoRouter.redirect = auth + dev guard (centralizado); AccessGuard = por rota (dentro da feature).
- (decision) AD-4 — Path constants na feature: cada *_routes.dart define constantes de path (ex: RhPaths.funcionarios) usadas tanto nas rotas quanto em context.go(). Binds: all features. Prevents: strings hardcoded espalhadas e typos de path. Rule: toda navegação usa a constante da feature-alvo; nunca string literal de path fora do *_routes.dart.
- (decision) AD-5 — Imports da feature são relativos (intra-feature) e do domain quando necessário: *_routes.dart importa screens e domain da própria feature com paths relativos. Binds: all features. Prevents: import circular entre features via routing. Rule: *_routes.dart importa apenas: (1) go_router, (2) screens e domain da própria feature, (3) AccessGuard de common_widgets.
- (decision) AD-6 — state.extra tipado [ASSUMPTION]: rotas que usam state.extra (almoxarifado/movimentacao) mantêm o extra tipado com cast no builder da feature; migração para path/query params é DEFERRED. Binds: almoxarifado. Prevents: quebra de API durante a refatoração. Rule: não alterar assinaturas de screen/extra nesta refatoração.
- (decision) AD-7 — Agrupamento de features em módulos de rota: (1) auth (login), (2) developer, (3) construtoras (inclui membros), (4) obras (dashboard), (5) lotes, (6) almoxarifado, (7) diario, (8) rh (funcionarios + chamadas), (9) epi, (10) financeiro, (11) validacao, (12) despesas_adm, (13) fornecedores, (14) compras_parcelas, (15) custos_360. Binds: all. Prevents: feature sem rota definida ou rota órfã. Rule: toda rota pertence a exatamente uma feature.
- (version) go_router: ^18.0.1 (pubspec.yaml); RouteBase é a base class de GoRoute; List<RouteBase> é o tipo do atributo routes.
- (assumption) [ASSUMPTION] Não há planos de usar go_router_builder para code generation no curto prazo; path constants manuais bastam.
- (assumption) [ASSUMPTION] As rotas de custos_360 pertencem ao módulo custos_360, não ao despesas_adm, mesmo que ambos usem module: adm no AccessGuard.
